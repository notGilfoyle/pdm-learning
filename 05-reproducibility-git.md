# Phase 5 — Reproducibility & Git (Theory + Practical)

**Goal:** Lock in what makes pdm projects reproducible, decide what to commit vs ignore, finish
your local git history, and (optionally) push to GitHub when you're ready.

---

## Theory

### What to commit vs ignore

| File / folder | Commit? | Why |
|---------------|---------|-----|
| `pyproject.toml` | ✅ Yes | Your project's intent and metadata. |
| `pdm.lock` | ✅ Yes | The whole point of reproducibility — pins the exact tree. |
| `app.py`, `test_app.py`, source | ✅ Yes | Your code. |
| `.venv/` | ❌ No | Rebuildable from the lock; huge; machine-specific. |
| `__pycache__/`, `*.pyc` | ❌ No | Generated bytecode. |
| `.pdm-python` | ❌ No (usually) | Records a local interpreter path; machine-specific. |

> **Rule of thumb:** commit *intent* and the *lock*; ignore anything pdm can regenerate.

### The reproducibility loop

The payoff of everything you've learned:

```
clone repo  →  pdm install  →  identical environment
```

Because `pdm.lock` pins every direct and transitive dependency with hashes, `pdm install`
rebuilds the *exact* environment the author had — on any machine, any time. No "works on my
machine."

## Practical

### 1. Create a `.gitignore`

In the **repo root** (`/Users/roshan/code/pdm-learning`), create `.gitignore`:

```gitignore
# Virtual environments (rebuildable from pdm.lock)
.venv/
**/.venv/

# Python bytecode
__pycache__/
*.py[cod]

# pdm local interpreter pointer (machine-specific)
.pdm-python

# OS noise
.DS_Store
```

> Note we **keep** `pdm.lock` tracked — it must stay in git.

### 2. If `.venv/` was committed earlier, untrack it

If you committed before adding `.gitignore`, remove the venv from git's index (this does **not**
delete the folder, just stops tracking it):

```bash
cd /Users/roshan/code/pdm-learning
git rm -r --cached myapp/.venv 2>/dev/null || true
```

### 3. Commit the final state

```bash
git add .
git commit -m "Phase 5: .gitignore, reproducibility notes"
git log --oneline
```

You should see a clean history of one commit per phase.

### 4. Prove reproducibility for yourself (optional but satisfying)

Simulate a fresh clone:

```bash
cd /tmp
rm -rf myapp-clone
git clone /Users/roshan/code/pdm-learning myapp-clone
cd myapp-clone/myapp
pdm install          # rebuilds the exact env from pdm.lock
pdm run test         # passes — same environment as the original
```

Delete `/tmp/myapp-clone` when done.

## Optional: push to GitHub

You're authed with `gh` (as `notGilfoyle`). When you're ready to publish, from the repo root:

```bash
cd /Users/roshan/code/pdm-learning

# Create a new repo on GitHub and push your current branch in one step.
# Use --public or --private as you prefer.
gh repo create pdm-learning --private --source=. --remote=origin --push
```

What this does:
- creates `github.com/<you>/pdm-learning`,
- adds it as the `origin` remote,
- pushes your local commits.

After that, day-to-day:

```bash
git add .
git commit -m "..."
git push
```

> Prefer the web flow? Create an empty repo on github.com, then:
> ```bash
> git remote add origin git@github.com:<you>/pdm-learning.git
> git push -u origin main
> ```
